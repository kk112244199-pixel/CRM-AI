来源：通用编写要求，已逐条判断。不合理的按「意图保留、字面修正」写入，避免做不到的流程把项目卡死。

本文件与 [PRD.md](./PRD.md)、[tech-selection.md](./tech-selection.md)、[eval.md](./eval.md) 同级生效。实现时先读本文件再改代码。

## 修正：测试与落盘（原第 5 条）

Node/Vite/SQLite **无法对尚未写到磁盘的文件跑测试**。按字面「先测通过再输出本地」做不到。

采用等价且可执行的约定：

1. 函数、HTTP 接口、表 ACL、handoff schema **必须有测试**。
2. 代码与测试**写入工作区后立刻跑**对应该步骤的测试。
3. **测试未通过 = 本步骤未完成**，不得开始下一步，不得把失败实现当成交付。
4. 不把「先写一堆无测试的页面再补测」当完成。

黄金切片（需 `DASHSCOPE_API_KEY` 或 `CURSOR_API_KEY`）允许在无密钥环境跳过，但必须在 eval 报告里标明跳过，不得假装通过。

## 分步与契约（原第 2、3 条）

顺序：`M0 文档` → `M0.5 前端点击原型（无后端）` → `M1 种子与库` → `M2 harness` → `M3 控制台接真 API` → `M4 Docker` → `M5 eval` → `M6 视觉` → `S9` 向量。`S10` 筛选/CSV 需 git 远程。何时打 `/` 见 [skill-timeline.md](./skill-timeline.md)。

每个里程碑结束必须留下清单与契约（先有文件，下一步才能开工）：

| 文件 | 作用 |
|---|---|
| `docs/checklists/M{n}.md` 或 `docs/checklists/S{n}.md` | 本步做了什么、命令、通过/失败 |
| `docs/contracts/M{n}.md` 或对应 S 契约 | 下一步必须遵守的接口、表、ACL、阶段名、禁做项 |

下一步开始时先读**上一份契约**，与 PRD 冲突时停下来问，不得默默改契约。

## 数据（原第 6 条）

不用真实客户、真实手机号、真实聊天记录。交付时提供：

- `data/corpus/`：8 家邮件/转写/企微摘录/手册/案例
- SQLite 种子：线索、阶段、示例 handoff
- `npm run test` / `eval:report` 用的夹具

「真实」在本项目里 = 字段和话术像国内销售，不是生产库导出。

## 注释（原第 8 条）

关键处用中文注：ACL 禁写、HITL 闸门、Token 入账、顺序调度、为何不用 Redis/MQ。类型名、路由、表名保持英文标识符，与代码生态一致。

## 覆盖矩阵（原第 9 条）

背景要求必须能在文档或 eval ID 上对上号。新增背景需求先改 PRD 再改代码。

| 背景点 | 落点 |
|---|---|
| 多智能体可见 | PRD §5–6，eval Q1 Q2 |
| 国内阶段与语料 | PRD §4–5，eval Q5 Q7 |
| Token 可见消耗 | PRD §8，eval R2 |
| HITL/HOTL | PRD §5–6，eval Q4（转化/外发/赢单，非每步） |
| 逻辑沙箱 | tech-selection，eval R4 |
| 不做 Redis/MQ/Grafana | tech-selection（课程未点名） |
| RAG 预留非 GraphRAG | tech-selection，S9 |
| Docker/nginx | PRD §12，M4 |
| 测试评估 | eval.md |

## 不确定则问（原第 7 条）

下列情况先问再写：改四 Agent 顺序、改 8 家名字、加回 Redis/MQ、把 Token 做成充值、暴露 Agent 端口给浏览器。
