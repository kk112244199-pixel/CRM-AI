## 调度（Q1）

同一条线索 **await 顺序**交卷，禁止 `Promise.all` 四个 Agent，禁止兄弟直连。

1. ingest：`orchestrator`（已生效）→ `lead-intake`（已生效）→ `pipeline` 转化建议（**待确认**）
2. 销售确认转化后才插入 account/contact/opportunity（阶段固定 `需求确认`），再拉 `followup`（**待确认发出**）
3. 销售确认发出后 `activities.effective=1`
4. 任一步失败：handoff `失败`，**后续 Agent 不再改库**（R3）

`POST /api/leads/ingest` 只跑到转化待确认，确认后再跟进；语义不可改成四个 Agent 同时开工。

## ACL（R4 / Q2）

执行 [M1.md](./M1.md) 白名单：

| Agent | 可写 | 禁止 |
|---|---|---|
| orchestrator | agent_runs, handoffs, leads.owner_user_id | accounts / contacts / opportunities / activities |
| lead-intake | leads（不含转化落地、不含 stage） | opportunities.stage、activities |
| pipeline | accounts, contacts, opportunities | activities |
| followup | activities（必须带 type） | opportunities / opp.stage |

越权：拒绝、写 `audit_events.action=acl-deny`、handoff 失败、不应用业务写入。

## JSON（Q3）

Agent 输出必须能抽出含 `summary` 的 JSON 对象。非法 JSON 不得写入业务表，只留失败 handoff 与 Token 行。

## Token（R2）

每次 run 同时写 `agent_runs` 与 `token_ledger`（prompt_tokens、completion_tokens、estimated_cny）。

`GET /api/usage` 的 `total` **必须等于**各 `agent_runs` 之和，且等于 `token_ledger` 之和。无充值表。无官方单价时估算 `(prompt+completion)*0.0002`。

## HITL（Q4 部分）

- 分配 / 建档：自动已生效
- 转化 / 外发：sales 或 manager 确认
- 需求确认 / 方案报价 / 谈判：sales 自推（harness `advanceStage`；HTTP 阶段推进留 M3 控制台）
- 赢单 / 丢单：仅 manager；sales 确认 403
- viewer：只读（ingest/confirm/abort 403）
- 拒绝转化：不建三对象、不跟进
- 中止：待确认/进行中改为 `已中止`，已生效/失败行保留

## HTTP

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/leads/ingest` | `{ leadId?, text }`。缺 leadId 时默认橙果。顺序跑到转化待确认，确认后再跟进 |
| GET | `/api/leads` | 列表 |
| GET | `/api/leads/:id` | 卡片 + 时间线 + 三对象 + 活动 |
| POST | `/api/handoffs/:id/confirm` | HITL 确认 |
| POST | `/api/handoffs/:id/reject` | HITL 拒绝 |
| POST | `/api/runs/:id/abort` | 中止后续排队 |
| GET | `/api/usage` | Token 合计与各 run |
| GET | `/api/metrics` | Prometheus 文本预留 |
| GET | `/api/health` | 存活；可含 `runner`，**不含密钥** |

不要把 Agent 端口暴露给浏览器。不要把 `apps/web-demo` 接这些接口。真 UI = M3 `apps/web`。
