## HTTP 新增

### 筛选

```
GET /api/leads?status=&stage=
```

| 参数 | 取值 | 行为 |
|------|------|------|
| `status` | `新线索`、`已转化` | 省略 = 不按 status 过滤 |
| `stage` | `需求确认`、`方案报价`、`谈判`、`赢单`、`丢单` | 省略 = 不按 stage 过滤；匹配 `opportunities.stage`（经 `oppStage`）。未转化线索 `oppStage` 为 null，**不会**匹配任何 stage 过滤 |

- 两参数 **AND** 组合。例：`status=新线索&stage=方案报价` 返回 `[]`。
- 未知 `status` 或 `stage` → **400** `{ ok: false, error }`。
- 无参数：与 S9 行为相同（全部线索）。

### CSV 导入

```
POST /api/leads/import
```

- Body：JSON `{ csv: string }`（UTF-8，可选 BOM）。无额外 CSV npm 依赖。
- 必填表头列：`company,industry,contactName,sourceSummary`。可选列：`searchTags`。
- 每个有效行插入一条线索：`status=新线索`；`ownerUserId` null；`lastActivity='CSV 导入'`；无 account / contact / opportunity / activity。
- 公司名重复（与现有 `leads.company` 精确匹配，含八条 seed）→ 跳过并记录 reason，**不**整批失败。
- 空 / 缺失 `company` → 该行记入 `errors`；继续处理其他行。
- 任意成功插入后调用 `rebuildLeadVec(sqlite)`。
- 响应：`{ ok: true, imported, skipped, errors }`。
- 新 id 形如 `lead-csv-<slug>-<n>`；**不得**复用 seed id。
- 空 csv → **400** `{ ok: false, error: "需要 csv" }`。

## Web 语义

- 选「未转化」tab → 请求 `status=新线索`。
- 选某 stage chip → 请求 `stage=...`。
- 「全部」且无 stage → 省略对应 query 参数。
- 「待确认」继续仅客户端过滤 `pendingIds`。
- CSV 导入：file input；仅 `sales` / `manager` 可见；导入后刷新列表。
