## 库路径与表

库：`data/hengce.db`。解析见 `packages/domain/src/paths.ts`。

| 表 | 用途 |
|---|---|
| users | 演示账号，role = sales / manager / viewer |
| leads | 线索。status = 新线索 / 已转化。`search_tags` 供本步关键词检索 |
| accounts | 客户。转化后才有。`lead_id` 唯一 |
| contacts | 联系人，挂 account |
| opportunities | 商机。stage 见枚举。`lead_id` 唯一 |
| activities | 跟进。type 见枚举。`effective` 1=已生效，0=草稿 |
| agent_runs | 每次 Agent 跑。含 prompt/completion token 与估算金额 |
| handoffs | 时间线条目。含 hitl_kind |
| token_ledger | Token 台账行，挂 run |
| audit_events | 越权与关键动作 |
| documents | 语料元数据 + `content` 全文。**禁止向量列**（S9 再加） |

不做：报价单、合同、充值账户、Redis、MQ。

## 枚举（中文，禁止 Discovery/Demo）

- 线索状态：`新线索` `已转化`
- 商机阶段：`需求确认` `方案报价` `谈判` `赢单` `丢单`
- 活动 type：`电话` `企微` `邮件` `拜访`
- Agent id：`orchestrator` `lead-intake` `pipeline` `followup`
- 界面名：系统分配 / 建档 / 商机 / 跟进
- HITL：`confirm-convert` `confirm-send` `confirm-win-loss`
- 语料 kind：`email` `call-transcript` `wecom` `handbook` `win-or-loss-case`

## ACL（M2 必须执行，本步只落约定）

见 `packages/domain/src/acl.ts`。

| Agent | 可写 | 禁止 |
|---|---|---|
| orchestrator | agent_runs, handoffs, leads.owner_user_id | accounts / contacts / opportunities / activities |
| lead-intake | leads（不含转化落地） | opportunities.stage、activities |
| pipeline | accounts, contacts, opportunities | activities |
| followup | activities（必须带 type） | opportunities |

越权：拒绝并写 `audit_events`。兄弟 Agent 不互聊。

## HITL（M2 执行，交互仍遵守 M0.5）

- 分配、建档：自动已生效
- 转化：sales 确认后才插入三张对象
- 外发：sales 确认后 `activities.effective=1`
- 需求确认 / 方案报价 / 谈判：sales 自推
- 赢单 / 丢单：仅 manager
- viewer：只读

## HTTP（M2 接上，语义不可偷换）

本步仅 `GET /api/health`。M2/M3 实现：

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/leads/ingest` | 录入线索；顺序跑系统分配→建档→转化建议（确认后再跟进） |
| GET | `/api/leads` | 列表 |
| GET | `/api/leads/:id` | 卡片 + 时间线 |
| POST | `/api/handoffs/:id/confirm` | HITL 确认 |
| POST | `/api/runs/:id/abort` | 中止后续，历史 handoff 保留 |
| GET | `/api/usage` | Token 合计 = 各 run 之和 |
| GET | `/api/metrics` | 预留 |
| GET | `/api/health` | 存活 |

鉴权：sales / manager / viewer。Agent 不暴露给浏览器。不要把 `apps/web-demo` 接这些接口。真 UI = M3 `apps/web`。
