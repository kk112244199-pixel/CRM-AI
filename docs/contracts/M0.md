# 契约 M0（修订：企业骨架 + 多 Agent）

后续步骤把本文当作硬约束。要改先改 PRD 并问人。

## 产品

- 名称：衡策销管平台
- 主 UI：时间线交卷，对话框不是主入口
- 卖方：卖销售系统；8 家是客户不是 CRM 竞品
- 多智能体：时间线必须能区分 系统分配 / 建档 / 商机 / 跟进；orchestrator 禁止打扮成销售同事

## 8 家客户（表与语料只用这些字面）

杭齿精密机电、嘉兴精工装备、澄海医疗器械、橙果素质教育、邻里鲜超市、夜灯便利、海图进出口、江东水务物资。

相似：杭齿精密机电 ↔ 嘉兴精工装备；邻里鲜超市 ↔ 夜灯便利。刻意不像：海图进出口、江东水务物资。

橙果素质教育种子为 **未转化线索**。其余七家种子为已转化商机（阶段见 PRD）。

## 对象

线索 `leads`（新线索/已转化）→ 转化后 `accounts` + `contacts` + `opportunities`。  
商机阶段：需求确认、方案报价、谈判、赢单、丢单。  
活动 `activities.type`：电话、企微、邮件、拜访。  
不做报价单、合同表。

## Agent 顺序与写权限

1. orchestrator 系统分配 → 只写 handoff 与 lead.owner
2. lead-intake 建档 → 写线索字段，自动生效
3. pipeline 商机 → 转化建议；写三张对象；中间阶段销售自推；赢单/丢单待主管
4. followup 跟进 → 只写 activities，外发待确认

禁止兄弟直连。

## Token

每 run 记 prompt/completion token 与估算金额。无充值表。

## 闸门

低风险自动（分配、建档）。  
sales：确认转化、确认外发、推进非赢单阶段。  
manager：确认赢单/丢单。  
viewer：只读。

## 技术禁区

Redis、RabbitMQ、Prometheus+Grafana 服务、独立向量库、GraphRAG、emoji、真实个人隐私、CPQ。
