# M0.5 前端点击原型（无后端）

状态：M0.5 **已实现并按企业骨架修订**（闸门放宽、对象拆分）。M6 已交付真控制台视觉；**本文件仍只约束无后端 demo**，不要拿它改 `apps/web` 的漏斗轨。

启动：`npm --prefix apps/web-demo run dev`  
测试：`npm --prefix apps/web-demo test`  
清单：[checklists/M0.5.md](./checklists/M0.5.md) · 契约：[contracts/M0.5.md](./contracts/M0.5.md)

## 为什么要插这一步

M1 造数、S7 接真 API、S8 才谈长得好看——这三条不变（S7/S8 均已交付）。

插入 M0.5 只解决另一件事：你能不能先 **点按钮**，看系统分配 / 建档 / 转化 / 跟进、闸门和 Token 的方向对不对。不经过 SQLite、不经过 Cursor SDK、不经过 nginx。点完你说「流程不对」，改的是这份原型和契约，而不是已经写好的库表。

因此顺序是：

`M0 文档` → **`M0.5 点击原型`** → `M1 真库造数` → … → `S7/M3 把原型里的假状态换成真 API` → `S8 视觉`

视觉在 **本步（M0.5）禁止**。本步允许「难看但能点」。不要 `/frontend-design`（视觉已在 M6 只改 `apps/web`）。

## 范围

In:

- 单独目录 `apps/web-demo/`（Vite + React），**禁止** `fetch`、禁止 WebSocket、禁止连 `localhost` API
- 状态全部在浏览器内存（`apps/web-demo/src/mock/machine.ts` 与 `seed.ts`）
- 8 家公司名必须与契约 M0 字面一致
- 五屏：线索列表、线索详情（时间线主）、待确认、用量、一个次要「录入」入口
- 用 `setTimeout` 模拟 Agent 思考，按 **orchestrator → lead-intake → pipeline → followup** 排队出现 handoff
- 按钮会改本地状态：确认 / 拒绝 / 中止
- 假 Token 数写在每条 handoff 旁，顶栏合计等于各条之和
- 交互状态机抽成纯函数，用测试锁住「点什么出现什么」（无后端也要测）

Out:

- `apps/api`、SQLite、Drizzle、`@cursor/sdk`、Redis、MQ、Docker
- 真模型、真 Token 计费
- 美化、emoji、图标库堆砌
- 把 demo 当成以后的生产前端（S7 新建或改造 `apps/web` 接 API；demo 可留作对照，不在 demo 里接后端）

## 你要能点出来的效果

以「橙果素质教育」走一遍黄金切片（种子阶段是新线索，适合从头演）。

| 你点什么 | 模拟出现什么 | 不应出现 |
|---|---|---|
| 列表点「橙果素质教育」 | 进入详情；显示未转化 | 直接当商机 |
| 「提交获客并分配」 | 先出现系统分配（自动已生效） | 四个 Agent 同时出现；调度被写成销冠 |
| 约 0.8 秒 | 建档自动已生效，仍无客户三对象；无需确认新建 | 未转化就改商机阶段；停在建档不再出商机卷 |
| 再约 0.8 秒 | 右侧时间线出现商机转化建议（待确认） | 建档后永远「模拟思考中」、没有「确认转化」 |
| 「确认转化」（右侧时间线） | 左侧出现客户+联系人+商机=需求确认 | 转化前左侧就有三对象；跳过转化 |
| 再约 0.8 秒后「确认发出」 | 电话活动生效；四份 handoff | 第五个 Agent；类型不是活动 |
| 已转化线索「推进到谈判」 | 销售直接改阶段 | 每次推进都要经理 |
| 「建议赢单」 | 待主管确认；切 manager 才能过 | 销售自己把阶段改成赢单 |
| 「拒绝」转化 | 无客户对象、无跟进 | 拒绝后仍转化 |

另外两家用于点「方向」但不跑完整切片也行：列表能看到杭齿精密机电（方案报价）和江东水务物资（丢单）。相似检索本步可用写死结果：「和杭齿很像 → 嘉兴精工装备」，点一下出一条提示即可，不做向量。

## 页面字段（线框级，非视觉）

线索列表：公司名、行业、阶段、最后活动。

详情左：公司、阶段、联系人占位、来源摘要。  
详情右（主）：时间线，每条含角色名、状态（进行中/待确认/已生效/已拒绝）、摘要、假 token、确认/拒绝（仅待确认且角色允许时）。

待确认队列：跨线索汇总所有「待确认」条目，点进去回到详情。

用量：本会话假合计 + 按 Agent 四列。

录入：一个文本框 + 提交；提交后仍回到该线索时间线，不把对话框当主 UI。

## 技术约束

- 不引用 `@cursor/sdk`
- 不新增后端端口
- `npm --prefix apps/web-demo test` 覆盖状态机（至少：顺序四步、拒绝截断、Token 合计）
- 启动：`npm --prefix apps/web-demo run dev`，只开前端端口
- 文案中文、无 emoji
- 关键状态流转用中文注释

## 和 S7 / S8 的关系

| 步 | 职责 |
|---|---|
| M0.5 | 假数据、假延迟、真按钮，给你纠方向 |
| M1 | 真 SQLite 与语料，仍无需要你点的完整产品 UI |
| M3/S7 | `apps/web` 接真 API，交互必须遵守 M0.5 契约（顺序、闸门、时间线为主） |
| M6/S8 | `/frontend-design` 才谈好看 |

若 M0.5 点完你要求改顺序（例如先 pipeline 再建档），必须先改 PRD 和契约，再造 M1 的数。
